💡 Azure Hybrid Benefit: Existing SQL Server licenses with Software Assurance can reduce Azure SQL Database costs by up to 40%. This is the answer when asked about cost reduction with existing licenses.
📝 SQL Language Categories (DDL / DML / DCL)
CategoryFull nameStatements
DDLData Definition LanguageCREATE, ALTER, DROP, TRUNCATE, RENAME
DMLData Manipulation LanguageSELECT, INSERT, UPDATE, DELETE
DCLData Control LanguageGRANT, REVOKE, DENY
⚠ TRAP: GRANT and REVOKE → DCL, NOT DML. DROP → DDL, NOT DML. INSERT → DML ✅
SQL Clause Order: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY
Memory: "Some Friends Watch Great Hollywood Operas"
🔐 ACID Properties
LetterPropertyDefinitionHook
AAtomicityAll statements succeed or ALL roll back. No partial commits."Atom" = indivisible
CConsistencyDB moves from one valid state to another. All rules/constraints respected."Consistent" = always valid
IIsolationConcurrent transactions don't see each other's uncommitted changes."Isolated" = separated
DDurabilityOnce committed, data survives failures. Logged to disk."Durable" = permanent
⚠ TRAP: "All data changes will be logged and accounted for" → This is Durability, NOT Consistency. Consistency = DB stays in a valid state per its rules.
⚠ TRAP: "Processes can see only data in a consistent state" → This is Isolation, NOT Consistency.

ObjectDefinitionKey fact

Non-Relational Data on Azure

~20%
🌐 Azure Cosmos DB APIs
APIData modelTrigger word
NoSQL API (Core)JSON documentsDefault Cosmos DB, document store
MongoDB APIJSON documents (BSON)MongoDB workloads, JSON + SQL queries
Gremlin APIGraph (nodes + edges)"relationships between entities", networks, social graphs
Table APIKey/value pairs"key/value", Azure Table Storage upgrade
Cassandra APIColumn-family (wide-column)High write throughput, Apache Cassandra workloads
⚠ TRAP: Key/value → Table API, NOT Cassandra API. Cassandra = wide-column (column-family). Very commonly confused!
💡 Throughput levels in Cosmos DB: Can be set at database level or container level. NOT at item or partition level.
📊 NoSQL Data Models
ModelStructureBest forAzure service
DocumentSelf-contained JSON/XML docsCatalogs, user profiles, contentCosmos DB (NoSQL/MongoDB API)
Key/ValueUnique key → valueSessions, caching, preferencesCosmos DB (Table API), Redis
GraphNodes + edges (relationships)Social networks, fraud detection, network topologyCosmos DB (Gremlin API)
Column-familyRows with flexible columnsHigh write throughput, IoT, time-seriesCosmos DB (Cassandra API)
⚠ TRAP: "Relationships between utilisation levels of network devices" → Graph database. Not columnar! Graph = nodes + edges = network topology.
💾 Azure Storage Services
ServiceProtocol/AccessBest forKey fact
Blob StorageREST / HTTP/HTTPSUnstructured data (images, video, backups)Object store; 3 tiers: Hot, Cool, Archive
Azure FilesSMB v3 / NFSCloud file shares, lift-and-shift file serversMount as network drive
Azure Table StorageREST / ODataKey/value structured dataNoSQL; Cosmos DB Table API = premium version
Azure Queue StorageREST / HTTPMessage queuing between servicesDecouples application components
⚠ TRAP: SMB protocol → Azure Files, NOT Blob Storage. Blob uses REST/HTTP. Azure Files is the only storage service mountable as a network drive via SMB.
💡 ADLS Gen2: Azure Data Lake Storage Gen2 = Blob Storage + hierarchical namespace enabled. Used for big data analytics. Parquet files live here.

🏭 Azure Data Factory — Activity Types
Activity typePurposeExamples
Data movementMoves data from source to destinationCopy activity
Data transformationReshapes / processes dataMapping data flow, Stored Procedure, Databricks Notebook
ControlOrchestrates pipeline logic & flowLookup, ForEach, If Condition, Wait, Execute Pipeline
⚠ TRAP: Lookup = Control activity — NOT transformation. It retrieves a value to drive pipeline logic. This is the most common ADF trap on the exam.
⚠ TRAP: Mapping data flow = Data transformation — NOT control. It reshapes data visually (joins, aggregations, filters).
⭐ Star Schema & Analytical Models
ConceptDefinition
Fact tableCentral table containing measurable data (sales amounts, quantities, revenue)
Dimension tableSurrounding tables with descriptive attributes (Date, Product, Customer, Geography)
MeasureNumeric value that can be aggregated (SUM, AVG, COUNT)
DimensionCategorical attribute used to slice/filter data
CubeMultidimensional structure formed where dimensions intersect
Star schemaFact table surrounded by denormalised dimension tables
Snowflake schemaLike star schema but dimension tables are further normalised
⚠ TRAP: "Any point where dimensions intersect represents ___" → a cube, NOT an aggregated measure. The measure lives at the intersection; the cube is the structure itself.

🔄 ETL vs ELT
ETLELT
OrderExtract → Transform → LoadExtract → Load → Transform
Where transformOutside the target (staging area)Inside the target (data warehouse / lake)
RequirementSchema defined before loading (schema on write)Schema applied on read (schema on read)
Best forRelational warehouses, sensitive dataData lakes, big data, Synapse
⚠ TRAP: ETL requires "data that is fully processed BEFORE being loaded" — not a matching schema in source and target, and not that target must be relational.
